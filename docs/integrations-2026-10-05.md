# 1С Fitness и Calltouch: проверка 5 октября 2026

Объект: открытый бассейн, подразделение ОПБ в 1С, проект 52900 «Открытый Бассейн» в Calltouch.

## Расписание и личный кабинет

- На сайте `/raspisanie` была статическая таблица: часы работы повторялись в ячейках свободного плавания, а для групп стояло «По записи». Подключения к 1С у таблицы не было.
- В 1С есть интеграция «Виджет расписания». Карточка настроек при двух попытках завершилась ошибкой. Подробный текст: `Поле объекта не обнаружено (СписокСпособовОтправки)` в форме `ФормаНастройкиВиджетаРасписания`, строка 76. Похоже на несовпадение версии конфигурации и данных интеграции; исправление требует администратора/поддержки 1С. Поэтому код виджета, его адрес и настройки доступа к расписанию ОПБ пока не получены.
- В 1С также есть интеграция мобильного приложения клиента и Fox Fit (ClientApp) для ОПБ. Сайт уже ссылается на приложения «ФК Наутилус».
- Документация вендора: [настройка виджета и личного кабинета](https://www.fitness1c.ru/knowledge-base/integratsii/vidzhet-raspisaniya-i-lichnogo-kabineta/lichnyy-kabinet/) и [API v2](https://www.fitness1c.ru/api2/). API предусматривает получение расписания, но для рабочего подключения нужны адрес базы ОПБ, terminalid, права и подтверждённый формат ответа.
- Для запуска веб-кабинета нужно восстановить доступ к настройкам виджета в 1С, получить код/адрес именно для ОПБ, включить нужные типы занятий и вход клиента, затем проверить запись и отмену на тестовом клиенте. До этого не публиковать форму авторизации или сетку занятий с фиктивными данными.

## Calltouch

- В 1С интеграция Calltouch для ОПБ включена и отображает статус «Подключена».
- В Calltouch активен вебхук лидов «ОПБ» в 1С, метод POST, передаются все 86 параметров. Старый дубликат вебхука выключен.
- Сайт загружает скрипт Calltouch, получает sessionId при отправке формы и регистрирует заявку через Calltouch Requests API проекта 52900. В Calltouch автоформы не настроены, потому что сайт использует API.
- Общая подмена номеров включена. Для обоих номеров, используемых в правилах подмены, есть настройки. Мониторинг исчезновения скрипта в Calltouch выключен.
- В журнале сделок Calltouch за 28 сентября - 4 октября 2026: 280 сделок, 233 без цифрового следа (83,2%), 230 из них с контактными данными. Найдены 38 сопоставлений по звонку и 10 по заявке. В журнале есть массовые операции БЧК и офлайн-источники. При этом в сделках приходят названия воронок и этапов, поэтому «Лид не найден» относится к сопоставлению с отслеженным обращением, а не обязательно к потере этапа воронки.
- Следующая проверка в 1С: выбрать несколько новых сделок с пометкой «Заявка с сайта» и «Лид не найден» и сопоставить их телефон, время создания и ID обращения с журналом лидов Calltouch. Отдельно посчитать продажи новым клиентам без БЧК, чтобы доля несопоставленных сделок отражала рекламную воронку. Перенастраивать импорт всех сделок или привязку по телефону до проверки примеров рискованно: можно ошибочно приписать офлайн-продажам рекламный источник.
